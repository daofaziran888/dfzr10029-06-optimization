# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

### 维度成员映射版本化（`/dimension_mapping`）

针对关联数据集连续刷新后维度成员沿用旧层级、页面短暂出现新旧父级混合的问题，提供独立的版本化处理链路：

- 输入为**维度成员映射**与**关联数据集刷新记录**；先清洗现有输入（去空白、丢空编码、同编码去重），再按映射版本做**成员级差异合并**，只写新增/父级变更/失效成员，不整表替换、不重复写入。
- 映射写入、刷新记录、维度刷新对照文件在 `store.lock` 的**同一提交边界**内完成，页面读取走快照，持久化前后成员归属一致。
- 并发刷新由「输入摘要幂等 + 前置版本乐观校验」控制，最终**只落一个有效版本**；冲突输入不生效，落「待核对」对照文件等待核对主版本边界。
- 维度刷新对照文件**保留来源输入**（原文、来源快照、提交边界标识），支持分析接口消费并持久化（刷新页面仍可回查）、按历史版本回退（回退文件沿用同一段来源可追溯）与 CSV 对照导出。
- 三张内部存储表（`dimension_member_mapping` / `dataset_refresh` / `dimension_refresh_checkpoint`）不计入业务模块概览。

验证脚本：`backend/tests/verify_mapping.py`（服务层与并发）、`backend/tests/http_e2e.py`（HTTP 端到端）、`frontend/tests/mapping.spec.ts`（页面验收）。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
